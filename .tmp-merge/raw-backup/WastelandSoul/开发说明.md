## 一之二、本地化的一个坑（务必记住，已经踩过）

tModLoader 的本地化文件名是 `Localization/<culture>_<prefix>.hjson`，其中 **`<prefix>` 是"共享前缀"**，
文件内容必须**相对该前缀**书写：

```hjson
# 正确：文件 zh-Hans_Mods.WastelandSoul.hjson
NPCs: {
	MechanicalCompanion: { DisplayName: 智械人 }
}

# 错误：又多套了一层 —— 实际键会变成 Mods.WastelandSoul.Mods.WastelandSoul.NPCs...
Mods: {
	WastelandSoul: {
		NPCs: { ... }
	}
}
```

**犯这个错的后果是"静默失效"**：不会报任何错，但所有本地化值都不生效，
游戏里只剩 tModLoader 按类名自动生成的英文名（`SalvagedSteelBar` → `Salvaged Steel Bar`），
自定义键（`Dialogue.*`）则直接显示键名。这就是上一版"整个模组全是英文"的原因。

另外两条经验：

- **自定义键要在 `Mod.Load()` 里注册**（见 `Common/WastelandText.cs` + `WastelandSoul.cs`），
  否则 `Language.GetTextValue` 拿不到值。
- tModLoader 会自动**重写**源目录里的本地化文件：把新注册的键补进去，
  其他语言缺的键会以 `// 注释` 形式写入英文占位，等翻译填。
  所以**源文件会自己变化**，属正常现象。

## 一之六、InnoVault 集成（清道夫 AI 改为状态机驱动）

`build.txt` 里已加 **`modReferences = InnoVault`** ——⚠️ **玩家必须同时安装 InnoVault**（你的环境里本来就有）。

用的主要是 InnoVault 的 `StateMachines` 子系统，把清道夫原来手写的
`switch (NPC.ai[2])` + `ai[1]` 倒计时 + 手写阶段判定**整体换掉**：

| 原来 | 现在 |
| --- | --- |
| `switch` 分发 7 个子状态 | 9 个 `[VaultState]` 状态类（`ScavengerStates.cs`），由 `NpcStateMachine<ScavengerContext>` 驱动 |
| 手写 `ai[1]` 倒计时 | 框架自带 `VaultState.Timer`（`OnEnter` 自动清零） |
| 手写 `ai[2]` 状态存/取 + 自己保证同步 | 框架把「当前状态 ID」写进 `NPC.ai[1]` 并**自动联网同步**，状态切换只传一个整数 |
| `UpdatePhase()` 用布尔+阈值自行判断 | `PhaseController.For(machine).OnHpBelow(...)`，阈值降序由框架保证（血从 70% 直掉 30% 只会触发最严格那条，不会被弱阶段抢先） |
| 阶段切换只是改数值 | 阶段本身变成**演出状态**（`ScavengerPhaseTwo/ThreeState`）：播吼叫、提示、粒子，40 帧后自动回到待机 |

槽位分配（重要）：`ai[1]` = 状态机（框架占用）、`ai[0]` = 阶段序号、`ai[3]` = 过载自毁标记（掉落判定用），
其余 `localAI[]` 仍用于无人机/污染团的冷却。

**已验证**：编译 0 errors / 0 warnings；加载自检通过；并用加载日志确认
**9 个状态全部被 InnoVault 成功收集**（`VaultStateRegistry<ScavengerContext>.Count == 9`）。
⚠️ 但**实际战斗表现（状态切换是否顺滑）仍需你进游戏打一场确认**——那是静态检查覆盖不到的部分。

### InnoVault 里还没用、但对后续很有用的东西

| 子系统 | 用途 |
| --- | --- |
| `Narrative/*` | 完整的**剧情/对话框架**：对话框、选项、回放（backlog）、进度键、奖励发放服务——很适合本模组「类似众神之怒的叙事密度」的定位，可以把智械人的对话从原版对话框升级成真正的剧情演出 |
| `Models3D/*` | glTF **3D 模型 + 骨骼动画**（需要模型资源文件）——如果以后想让智械人或 Boss 用真 3D 模型 |

| `TileProcessors/GlobalTileProcessor` | 图块处理；配合 `StructureHelper`（你也装了）做「壁炉」这类结构会更省事 |

工程实际目录：`E:\开发\WastelandSoul`


这样你在 `E:\开发` 里改代码，tModLoader 直接就能编译，不用来回拷贝。
（链接若被删掉，用 `New-Item -ItemType Junction -Path <上面的路径> -Target E:\开发\WastelandSoul` 重建。）

### 构建

**方式 A（推荐，游戏内）**：tModLoader → 模组源 → 找到 WastelandSoul → 生成模组。
游戏内构建会顺带做一次加载校验，最容易发现贴图/本地化问题。

**方式 B（命令行）**：`dotnet` 必须**在 tModLoader 安装目录下**执行（否则报 `Could not load file or assembly 'ReLogic'`），
并且**必须传工程目录的绝对路径**：

```bat
cd /d E:\steam\steamapps\common\tModLoader
dotnet tModLoader.dll -build E:\开发\WastelandSoul
```

> ⚠️ **踩坑记录（很重要）**：`-build` 的参数是**路径**（按当前目录解析），不是模组名。
> 如果只写 `-build WastelandSoul`，它会去编译 `<安装目录>\WastelandSoul`——
> 那个目录不存在/为空，于是**编译出一个空程序集**，却照样打印
> `Compilation finished with 0 errors and 0 warnings`，生成的 .tmod 体积只有 9 KB、
> 里面只有 DLL/PDB/Info、没有任何贴图，加载时会报「命名空间与文件夹名不匹配」。
> 判断方法：看输出里有没有你源码的报错或警告（例如 `Scavenger.cs(82,4): warning CS0162`），
> 以及 .tmod 是否达到 **40 KB 量级**。

> 另注：命令行构建会在安装目录下临时生成 `WastelandSoul\compile_temp`，构建完成后可以删掉。

## 五、开发优先级 2：清道夫（Boss 1）

`Content/NPCs/Bosses/Scavenger/Scavenger.cs`

### 三阶段

| 阶段 | 触发 | 实现 |
| --- | --- | --- |
| 一：清扫协议 | 100%–60% | 机械臂近战横扫，范围大、**前摇 45 帧**（动作刻意不流畅）；**优先攻击血量最低的玩家**（程序判定「虚弱 = 污染严重」） |
| 二：过载修复 | ≤60% | 召唤**维修无人机**（最多 3 台，只给 Boss 回血、不攻击玩家，玩家必须优先清理）；移动**更卡顿**（卡顿间隔 14→20 帧）；攻击间隔缩短（150→105 帧）；破损推进器开始在地面留下**污染区域** |
| 三：协议崩溃 | ≤30% | 传感器碎裂 → **无差别攻击最近目标**；**每 3 秒锁定一次位置**发射 3 发子弹，出膛带随机延迟（设备老化造成的卡顿），位置锁定后不再追踪；残血（≤12%）进入**过载自毁式冲锋** |

### 过载自毁的结算规则（已按你的选择定稿）

**没能在冲锋前击败它 → 机体自毁，一件战利品都不给，也不推进剧情**（壁炉入口不开）。
因为清道夫每 5 天会再来一次，所以这不是死路。

- 判定入口是 `Scavenger.CountsAsPlayerDefeat(npc)`，**掉落条件与 `OnKill()` 的剧情推进共用它**，两者行为必然一致。
- 实现方式：`ModifyNPCLoot` 只在加载期运行一次（文档明确要求「动态行为必须放进规则本身」），
  所以掉落用了 `LeadingConditionRule` + 自定义 `IItemDropRuleCondition`（`DefeatedByPlayerCondition`）。
- 冲锋是否撞到过玩家记录在 `NPC.ai[3]`：`OverloadFailureMarker = -1`（自毁）、`OverloadFailureHitMarker = -2`（自毁且撞到过玩家）。
- 想改成「只有被撞死才没收掉落、躲过去就正常掉」：把 `Scavenger` 里的
  `NoLootOnAnySelfDestruct` 改成 `false` 即可（当前为 `true`，即只要进入自毁就没有掉落）。

### 掉落与剧情

- 精钢碎块 ×15–25、清道夫残片 ×1–2（**仅在正常击败时掉落**）
- 正常击败后 `OnKill()` → `WastelandStorySystem.MarkScavengerDefeated()`：解锁「壁炉入口开启」并给出世界提示

### 定期来袭（每 5 天一次）

`Common/Systems/ScavengerInvasionSystem.cs`

| 时刻 | 行为 |
| --- | --- |
| 世界创建后每 5 天的 **19:30** | 预警：「耳边仿佛传来刺耳声，空气弥漫着血腥气味……」 |
| 每 5 天的 **20:30** | 在随机一名存活玩家附近（水平 620–900 像素、上方 420 像素）生成清道夫 |

- 天数以世界创建当天为第 1 天，每天黎明 +1，随世界存档保存（`WorldDay`），进世界时同步给客户端。
- 时间判定用 `Main.time`：夜晚自 19:30 起算（`Main.time == 0`），所以 19:30 = 0 tick、20:30 = 3600 tick，
  不受白天/夜晚长度被改动的影响。
- **同时只允许存在一只清道夫**（`Scavenger.AnyAlive()`），生成前先检查。
- **玩家正常击败它之后停止定期来袭**（剧情已推进，之后由信号传感器决定何时再打）。
  想让它永远来袭：删掉 `PostUpdateWorld()` 里 `WastelandStorySystem.scavengerDefeated` 那个 `return`。
- 读档时若已经过了 20:30，会跳过预警直接生成（避免补一条已经没有意义的预警）。

### 信号传感器（召唤物）

`Content/Items/Summons/ScavengerSignalSensor.cs`

- **铁砧 + 5 个精钢** 制作（`TileID.Anvils` + `SalvagedSteelBar × 5`）

### 工程化：一条命令跑完「构建 + 校验 + 加载自检 + 装机」

`E:\开发\tools\ws_pipeline.ps1`：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File E:\开发\tools\ws_pipeline.ps1
```

依次执行并逐项打印 `[OK]/[FAIL]`（**顺序是刻意的，见「批次 11」第 3 节**）：

1. **先**从译文表重新生成汉化补丁的 `zh-Hans`、**拍快照**、并校验快照干净
   （`sync_cn_translation` + `check_cn_backup`）——必须发生在任何构建/加载**之前**
2. 构建 **汉化补丁 → 主模组**（要求 `0 errors and 0 warnings`）
3. 静态校验 10 项：`check_assets` / `check_localization` / `check_cn_parity` / `test_key_regex` /
   `test_quote_detection` / **`test_loadtest_detection`** / `sync_translation` / `ensure_ps1_bom` /
   `tmod_contents:main` / `tmod_contents:patch`
4. **隔离目录无头加载自检**（复制两个 .tmod 到 `.tml-loadtest-cn`，跑到 `Choose World:`）。
   失败模式：`Disabling` / `error CS` / `Unhandled exception` / `malformed` / `failed to load` /
   `error occurred while loading` / `automatically disabled` / `IOException`；
   并且**断言两个模组都出现在 `Adding Content`、且没有任何 `Unloading: <本模组>`**
   （自动从 `build.txt` 读 displayName——日志打的是显示名，不是内部名）
5. 复制进游戏真实 Mods 目录，并从**加载前拍的那份快照**还原补丁源文件
6. 加载之后从译文表**再同步一次**（tModLoader 加载时必定重写过源文件）

> 第 1 步与第 4 步都会清理 `*.legacy`：tModLoader 每次加载都会把
> `zh-Hans_Mods.WastelandSoul.hjson` 改名成 `.hjson.legacy`，下一次加载时
> `File.Move(..., overwrite:false)` 撞名抛 IOException，**会把补丁和主模组一起自动禁用**。

开关：`-SkipBuild` / `-SkipLoadTest` / `-SkipInstall`；末尾打印
`PIPELINE RESULT: all green` 或失败项清单。**已验证可全绿跑通。**

⚠️ **这个脚本必须带 UTF-8 BOM**：PowerShell 5.1 会把无 BOM 的 `.ps1` 按 ANSI 读，
中文路径全部变乱码（`E:\开发` 会变成 `E:\寮€鍙`）。而编辑工具保存的是无 BOM 的 UTF-8，
**所以每次编辑过它之后都要补回 BOM**（本机没有 PowerShell 7，没法靠 PS7 的 UTF-8 默认行为绕过）：

```powershell
$p='E:\开发\tools\ws_pipeline.ps1'
[System.IO.File]::WriteAllText($p,
  [System.IO.File]::ReadAllText($p,[System.Text.UTF8Encoding]::new($false)),
  [System.Text.UTF8Encoding]::new($true))
```

> 顺带教训：Python 脚本被 PowerShell 调用时要设 `$env:PYTHONIOENCODING='utf-8'`，
> 否则默认 GBK 控制台编码会让带中文/✓ 的 `print` 直接抛 `UnicodeEncodeError`。
> 这两点脚本里都已内置。

### 那 4 个参考模组的结论（都用真实证据核过，不是猜）

### 顺手修掉的两个"静默失效"（都比 Boss 本身更值得记住）

#### 1. 汉化补丁里**一个汉字都没有**（严重）

`WastelandSoulCN/Localization/zh-Hans_Mods.WastelandSoul.hjson` 打开是这样的：

```hjson
Items: {
	SoulFragmentScavenger: {
		// DisplayName: Soul Fragment I
		// Tooltip: A fragment of code pulled from Execution Unit-07. Machina needs this.
	}
}
```

**全是注释掉的英文占位**——是 tModLoader 自己补的骨架，从来没有填过中文。
而旧版 `check_tmod_contents.py` 的判定是「`zh-Hans` 文件存在且 **> 5000 字节**」，
这个 20KB 的空壳因此一路绿灯打进了 `.tmod`。**所以之前那几轮"中英双语"的说法是错的，游戏里一直是英文。**

现在：
- `tools/sync_cn_translation.py`：**以译文表为准**重建中文文件（304 个键 → 303 条中文，含多行 Tooltip），
  同时刷新 `E:\开发\.backup\WastelandSoulCN_zh-Hans.hjson`。
- `tools/check_cn_parity.py`：键一一对应 + 报出「非空但没有中文」的键。
- `check_tmod_contents.py` 改成**看内容**：统计包内中文文件的**汉字数量**（要求 ≥ 1000，实际 4274）。
- 流水线加了 `RunChecker check_cn_parity` / `test_key_regex` / `ensure_ps1_bom` 与
  `tmod_contents:main` / `tmod_contents:patch` 五项，并在**构建前**自动跑一次 `sync_cn_translation.py`
  ——否则 tModLoader 每次加载都会把源文件重写成空壳，下一次构建又会打出没有中文的包。

> 教训：**校验脚本能证明"没坏"，证明不了"东西真的在里面"。** 只按体积判断等于没判断。

#### 2. `check_localization.py` 把拼接片段当成了键（顺带踩到一个正则坑）

`WastelandMemorySystem.MemoryTextKey()` 里有
`"Mods.WastelandSoul.Dialogue.MechanicalCompanion.Memory" + Utils.Clamp(stage, 1, TotalMemories)`，
校验器把 `…Memory` 当成了完整键，于是报"缺失 1 条"（真实键是 `Memory1`~`Memory4`）。

修的时候第一次写成 `"..."\s*(?!\+)`，**是错的**：`\s*` 贪婪，负向断言失败后会回退成
"吃掉 0 个空白"，断言看到的是空格而不是 `+`，匹配照样成功。
现在改成「匹配候选 + 按闭合引号后的字符判断」，并加了 `tools/test_key_regex.py` 做回归测试。

> 教训：`\s*(?!X)` 这种写法在负向断言前放可空量词，等于给回溯留了后门。

#### 3. 附带：`ws_pipeline.ps1` 的 BOM 也要能自检

编辑工具保存的是无 BOM 的 UTF-8，而脚本里有 `E:\开发\...` 中文路径字面量，
Windows PowerShell 5.1 会按 ANSI 读成乱码。新增 `tools/ensure_ps1_bom.py`
（`--check` 只检查），并接进流水线——**每次改过 `.ps1` 都会自动补 BOM，不必再记这条规矩**。

## 批次 10 之二：修掉「汉化补丁被整个禁用」的致命 bug（本轮）

你让我看 `client.log`，里面的错误是：

```
The localization file "Localization/zh-Hans_Mods.WastelandSoul.hjson" is malformed and failed to load:
System.ArgumentException: Found '}' where a key name was expected (...) At line 26, column 27
[INFO] [tML]: Disabling Mod: WastelandSoulCN
[INFO] [tML]: Disabling Mod: WastelandSoul
```

**汉化补丁和主模组一起被禁用了**——也就是说上一个版本你进游戏根本看不到这套内容。

### 根因（不是猜的，是二分定位实测出来的）

中文文件里有两行是**未加引号、且以 `{` 开头**的值：

```hjson
LikeBiome: 这里的参数还算合意——{BiomeName}。      ← 能解析（花括号不在值首）
DislikeBiome: {BiomeName}让我想起被污染的地面。    ← 崩溃（值以 { 开头）
```

Hjson 看到值以 `{` 开头就把它当**内联对象**去解析，走到 `}` 处发现"这里应该是键名"
→ `Found '}' where a key name was expected. At line 26, column 27`。

那 **column 27** 也对得上：`{BiomeName}` 的第 26 列正好是第一个 `}`，
解析器把它当成"内联对象的结束"，于是第 27 列的第二个 `}` 就成了"意料之外的键名位置"。

### 规则是实测出来的，不是查文档猜的

Hjson 的文档说"未加引号的值不能含结构字符"，但这个说法**过严**：
按它去改会把英文文件里 `(19:30, arrival at 20:30)` 这种一直正常工作的值全判成错。

所以我做了个探针：一个最小模组 `HjsonParseProbe`，**每个用例一个本地化文件**
（tModLoader 遇到第一个语法错误就中止整个文件，塞在一起无法定位），
然后用 `tools/probe_hjson_rules.py` 做**二分定位**，让真实解析器给出判定。

**18 个用例的真实结论**（落在 `tools/hjson_quoting_rules.json`）：

| 值 | 结果 |
| --- | --- |
| 纯文本 | ✅ |
| 含逗号 `Every 5 days (19:30, arrival at 20:30)` | ✅ **合法** |
| 含冒号 `每 5 天一次（19:30 预警）` | ✅ **合法** |
| 含 `=`、`;`、`+` | ✅ 合法 |
| 花括号在**中间** `合意——{BiomeName}。` | ✅ 合法 |
| `[NPCName] is here`（以 `[` 开头） | ✅ 合法 |
| 以 `-` 或 `#` 开头 | ✅ 合法 |
| 值里有未转义的引号 `he said "hi"` | ✅ 合法 |
| 含反斜杠 `path C:\temp\x` | ✅ 合法 |
| **值以 `{` 开头** | ❌ **唯一会被拒的** |

→ 所以 `quote_value()` 现在**只对"以 `{` 开头"和"含双引号"加引号**，其余保持原样。
这样既能挡住致命错误，又不会去动那些本来就正常的英文值。

### 为什么我的校验器之前没抓到（第三次"静默失效"）

`check_localization.py` 用的是**自写的缩进解析器**，只看键的层级与是否存在，
**完全不校验 Hjson 的引号规则**——所以它对这份致命文件一路绿灯。

更糟的是**加载自检也放过了它**：tModLoader 把 hjson 解析失败写进
**`server.log`**，stdout 只有一行"see server.log for full trace"，
而我的自检只 grep 了 stdout 的 `out-*.log`。

| `tools/sync_cn_translation.py` | 新增 `quote_value()`：按实测规则给值加引号；中文文件已重新生成 |

### 修完引号之后立刻暴露的第二个问题：备份策略本身是坏的

```hjson
// 改写后
BossChecklist: {
	Scavenger.SpawnInfo: ...        // 而且值可能退回英文 / 被注释掉
}
```

键本身没变（都是 `Mods.WastelandSoul.BossChecklist.Scavenger.SpawnInfo`），

### 3. 你要的修复：备份快照必须在加载自检**之前**拍

**旧顺序（错）**：构建 → 静态校验 → **加载自检** → 装机（**在这一步从源文件刷新备份**）→ 从备份还原。

**为什么错**：tModLoader 在构建/加载时会重写源目录里的本地化文件——它把你的
`zh-Hans_Mods.WastelandSoul.hjson` 改名成 `.hjson.legacy`，并在原位置写入它自己那份**最小集空壳**。
所以"装机时从源文件刷新备份"= **把已经被削过的文件存成备份**，下次 `--restore` 再把损坏还原回来：
一个自我复制的错误。而"加载自检"恰好就是那个把源文件削掉的动作，它跑在刷新备份之前。

**新顺序（对）**：

| 步 | 动作 |
| --- | --- |
| 1 | **清理 `*.legacy` → 从译文表重新生成 zh-Hans → 拍快照 → `check_cn_backup` 证明快照干净** |
| 2 | 构建 汉化补丁 → 主模组 |
| 3 | 9 项静态校验（含包内容检查） |
| 4 | 隔离目录无头加载自检（这一步会削源文件，但快照已经拍好了） |
| 5 | 装机；从**加载前的快照**还原补丁源文件（**不再刷新备份**） |
| 6 | 加载后从译文表再同步一次 |

新增 `tools/check_cn_backup.py` 把这条规矩变成可验证的：

- 备份必须**等于**「译文表 + 主模组 en-US」算出来的权威输出（不一致就打印第一处差异的行号与内容）；
- 备份里汉字数 **≥ 1000**；
- 源文件与权威输出不一致时**只报 NOTE**——那是加载的必然结果，**快照干净才是重点**。

### 新增工具 `tools/apply_art.py`（以后每批美术都用它）

处理链（顺序是踩出来的）：

1. **抠品红不是"颜色相等"**：按「品红程度」`min(R,B) − G` 算 alpha
   （`≥90` 全透明、`≤30` 全保留，中间渐变）。这个量对骨白 `(−18)`、冷蓝 `(−54)`、
   深蓝 `(−60)` 全是负数或很小，所以**不会误伤角色本身的蓝白配色**，只有真品红会中招。
2. **色溢修正**：把半透明像素的 RGB 换成最近的**不透明**像素颜色（3 轮 8 邻域膨胀）。
   不做这一步，缩放后每个边缘都是脏紫色——AI 图的抗锯齿边缘就是这个来源。
3. 按 alpha 裁到包围盒 → 等比缩放（缩小 >3 倍用 **BOX 面积平均**，否则 LANCZOS）。
4. alpha 阈值化（`<32` 直接透明）。
5. **调色板量化**：只对 RGB 量化、alpha 原样保留，并且**先把透明区的 RGB 填成不透明均值**——
   否则品红像素会把调色板整条拉紫。
6. 居中写进目标画布；多帧资产按帧**纵向**堆叠。

### 三个技术决定（都写进代码注释了）

1. **同一只 Boss 的所有帧必须共用一个缩放比**（`common_scale()`）：
   每帧各自"填满画布"会让机体在动画里忽大忽小——因为机械臂伸出去的那几帧包围盒宽了一倍。
   共用比之后机体尺寸恒定，臂展变化才是"伸臂"而不是"变大"。
2. **会飞的单位"底边对齐"**（`place(..., align="bottom")`）：
   清道夫的 9 格本来就画了不同的推进器火焰长度（高/中/低悬浮），底边对齐才能保留这个上下浮动感；
   居中会把这点差异抹平。
3. **智械人帧序按原版城镇 NPC 惯例**：`0-3 下 / 4-7 上 / 8-11 右 / 12-15 左 / 16-20 站立 / 21-24 使用`，
   侧身只有朝右一张、朝左用镜像；内容高度 **42px**、脚底落在 `y=53`
   （参照本机能拿到的真实城镇 NPC `YoungBrewer`：内容 20×38、脚底离帧底 4px）。
   行走帧由**整体上下位移**（`(0,-1,0,1)`）派生，站立 5 帧与使用 4 帧同理。
