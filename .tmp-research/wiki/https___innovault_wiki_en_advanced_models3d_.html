Models3D

Models3D imports .obj / .gltf assets into Vault3DModel, then draws them via Model3DRenderer (a RenderHandle) in layered passes with skinned animation support. On Main.dedServ, loading returns Vault3DModel.Empty and no GPU resources are created.

ClientGPU only
Weight=5Draws after PRT
LayerModel3DLayer

Overview

Section titled “Overview”

Use for boss props, vehicles, weapons, environmental 3D objects: client visuals.

Use when:

  • Skinned glTF characters / boss models
  • Grounded or floating 3D decor (NPC / projectile PostDraw)
  • 3D content that must sort with tiles / players (Model3DLayer)

Don’t use when:

  • Server logic or hitboxes: use NPC / Projectile / Actor
  • Pure 2D sprite FX: use PRT
  • Full-screen post-process pipelines: custom RenderHandle (see RenderHandle)

Attach to NPC workflow

Section titled “Attach to NPC workflow”

Persistent 3D decor follows register → update → unregister. Gameplay logic stays on the NPC; Models3D is client draw only.

StepAction
1Autoload .gltf / .obj with [VaultLoaden] on a static Vault3DModel field
2In ModNPC.OnSpawn(IEntitySource source), guard with model.IsValid (server gets Empty)
3Create Model3DInstance, set Layer, Scale, optional AnimationPlayer
4Call Model3DRenderer.RegisterPersistent(_instance) once per spawn
5Each AI() tick, assign _instance.Position = NPC.Center and rotation from NPC.rotation
6Cross-fade clips on phase change via AnimationPlayer.Play("attack", fadeIn: 0.2f)
7On death or despawn, call Model3DRenderer.UnregisterPersistent(_instance) in OnKill
8Pick Model3DLayer so the mesh sorts with tiles/players as intended
9Do not read hitboxes or phase from the 3D instance on Main.dedServ
10Test on client: OBJ may need CullBackface = false; check model.Diagnostic on load failure

Key points:

  • Check model.IsValid before draw
  • Position is world pixels (framework subtracts screenPosition)
  • OBJ models often need CullBackface = false

RenderHandle pipeline

Section titled “RenderHandle pipeline”

Model3DRenderer extends RenderHandle, hooked into multiple Terraria draw stages. Weight = 5. After PRT (lower weight) to avoid clobbering particle canvas state.

Atomic API (DrawInstance, DrawMeshGroup, BuildWorldMatrix, etc.) can be reused in custom RenderHandle. Full-screen post-process, Weight ordering, and SpriteBatch contracts: RenderHandle.

Common issues

Section titled “Common issues”
IssueCause / fix
Model not visibleIsValid false; check path, logs, Diagnostic
Dedicated server empty modelExpected; Empty on server, GPU on client
Forgot UnregisterPersistentModel keeps drawing after entity dies; unregister in Kill
OBJ missing facesSet CullBackface = false
Animation frozenNo Animation; or clip name mismatch
Custom shader all blackNon-BasicEffect needs ConfigureEffect params
Draw order vs PRT wrongModels3D Weight=5 after PRT; restore RenderState if mixing
CastShadow does nothingReserved. Shadows not implemented yet

Caution

Models3D is client / GPU only. Do not rely on 3D models for gameplay logic on Main.dedServ or dedicated servers; put logic on server-visible NPC / Projectile / Actor entities.

Companion sample

Section titled “Companion sample”

InnoVaultExample · CrystalModel: the hand-written LowPolyCrystal.obj loads into a Vault3DModel via [VaultLoaden], and a persistent Model3DRenderer instance spins a crystal above the player while the projector is held; the comments explain why RegisterPersistent beats per-tick Submit (the transient queue flickers at high frame rates).
